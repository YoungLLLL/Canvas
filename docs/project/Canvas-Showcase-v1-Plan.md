# Canvas Showcase v1 工作计划

> 状态：当前执行基准  
> 更新日期：2026-07-20  
> 当前项目代号：Canvas  
> 目标：完成一个可公开访问、可持续扩展、具有高完成度视觉与动效的个人数字博物馆产品。

## 1. 产品定位

Canvas Showcase v1 不是一次人工策展，也不以短期用户验证为首要目标。它是一套可扩展的数字博物馆展示系统：客观呈现真实博物馆馆藏，并通过有规则、有来源边界的 AI 内容生成与艺术家人格，让用户能够观看、理解并围绕当前作品展开对话。

首个正式版本以芝加哥艺术博物馆为核心馆藏，建立未来接入更多博物馆时仍可复用的展示、数据、视觉、动效和 AI 规则。

## 2. Showcase v1 目标

- 建立独立、可识别、适合长期发展的产品品牌。
- 展示芝加哥艺术博物馆中符合图片与权利规则的美术作品，而不局限于三件精选作品。
- 建立可承载大量作品的馆藏浏览、筛选、搜索和详情体验。
- 完成约三个具有可信史料边界的艺术家人格。
- 让 AI 根据统一规则自动生成作品理解入口，而不是逐件人工策展。
- 形成一套有辨识度、可扩展的数字艺术视觉与动效系统。
- 将当前静态 Demo 迁移为可持续开发和公开部署的正式工程。
- 完成稳定性、性能、安全、响应式与项目展示材料。

## 3. 执行原则

1. **真实馆藏优先**：作品事实、图片、权利和来源以馆方及可靠资料为准。
2. **客观呈现优先**：系统提供理解入口，不替用户规定单一叙事或观看顺序。
3. **规则代替手工策展**：描述、问题、观察提示、关联和色板尽量由可复用规则生成。
4. **作品始终是主体**：地图、界面、动效和 AI 都服务于观看，不与作品竞争注意力。
5. **AI 必须可追溯**：明确区分事实、解释、推测与数字化身表达。
6. **设计先行但分阶段精修**：迁移前锁定视觉与动效规则，迁移后基于真实数据完成最终精修。
7. **渐进迁移**：保留当前 Demo 作为视觉和交互基准，不进行无验证的一次性重写。
8. **只展示有权展示的内容**：不得根据艺术家年代推断图片许可。

## 4. Showcase v1 范围

### 4.1 包含范围

- 全球博物馆入口与芝加哥艺术博物馆入口。
- 芝加哥艺术博物馆馆藏的分页浏览、搜索和基础筛选。
- 符合展示规则的作品图片、元数据、权利信息与馆方来源。
- 作品独立页面与可分享链接。
- 高清查看、缩放、拖动、复位和全屏。
- AI 自动生成的作品简介、观察提示、推荐问题、标签、关联和无障碍描述。
- 约三个艺术家人格及其作品上下文对话。
- 回答依据、证据边界和数字化身声明。
- 桌面端最佳体验与可用的移动端体验。
- 项目介绍、品牌分享信息和公开部署。

### 4.2 暂不包含

- 人工逐件策展或人工编排全部观看路径。
- 登录、收藏、评论、社交、付费和用户内容。
- 写实 3D 博物馆复刻。
- 为所有艺术家开放人格对话。
- 复杂的艺术家生涯路线与地点地图。
- 在图片权利不明确时直接展示作品图片。
- 为追求数量而接入更多博物馆；Showcase v1 先把芝加哥模式做完整。

## 5. 工作阶段与顺序

### 阶段 0：产品命名与品牌命题

这是所有后续工作的最高优先级任务。`Canvas` 在名称确定前仅作为项目代号。

- [ ] 明确品牌希望首先传达“观看”“博物馆空间”还是“作品回响”。
- [ ] 明确英文、中文及双语使用策略。
- [ ] 明确产品副标题和一句话描述。
- [ ] 围绕 3–4 个方向生成候选名称。
- [ ] 按读写、记忆、气质、扩展性和混淆风险筛选。
- [ ] 检查搜索结果、域名、软件目录、社交账号和同行名称占用。
- [ ] 将最终候选放入首页字标、浏览器标题和分享卡片中比较。
- [ ] 确认正式名称后再更新仓库、页面元数据和视觉资产。

完成门槛：确定正式名称、基础字标方向、产品副标题和可使用的主要域名方案。

### 阶段 1：完整馆藏展示与版权规则

- [ ] 定义“可陈列作品”的资源类型边界。
- [ ] 定义公共领域、明确许可、仅元数据展示和禁止展示规则。
- [ ] 定义缺图、低清图、异常比例和失效图片的处理方式。
- [ ] 定义馆方署名、来源链接和许可信息的展示位置。
- [ ] 明确芝加哥馆藏 API 的分页、字段和更新策略。
- [ ] 明确本地缓存、服务端缓存与内容刷新策略。
- [ ] 形成可复用于其他博物馆的数据接入规范。

完成门槛：任何馆藏记录都能由规则确定是否展示图片、展示哪些信息以及如何署名。

### 阶段 2：信息架构与页面状态

- [ ] 确认首页、博物馆、馆藏、作品和艺术家页面结构。
- [ ] 定义稳定且可分享的页面路由。
- [ ] 定义搜索、筛选、排序、分页和返回状态恢复。
- [ ] 定义作品页中观看、资料、对话和来源之间的关系。
- [ ] 定义加载、空结果、错误、无网络和 AI 不可用状态。
- [ ] 定义桌面端和移动端的功能差异。

完成门槛：所有核心页面、状态和跳转均有明确说明，不依赖默认画面猜测实现。

### 阶段 3：迁移前视觉与动效系统

- [ ] 建立颜色、字体、间距、圆角、阴影和层级 Token。
- [ ] 设计大量馆藏下的网格、画廊及筛选界面。
- [ ] 定义横版、竖版、方形、超长比例和缺图作品规则。
- [ ] 定义地图、馆藏、作品查看和对话的视觉层级。
- [ ] 建立动效时长、缓动、位移、缩放、模糊和透明度规则。
- [ ] 定义减少动态模式与移动端降级方式。
- [ ] 在当前 Demo 中验证地球到馆藏、作品卡到查看器、对话展开等高风险交互。

完成门槛：目标体验已经定型，正式工程的组件结构能够据此设计。

### 阶段 4：数据模型与正式工程

- [ ] 定义博物馆、艺术家、作品、图片、权利和来源类型。
- [ ] 定义 AI 生成内容、人格版本和生成状态类型。
- [ ] 建立运行时数据校验。
- [ ] 创建 Next.js、React、TypeScript 正式工程。
- [ ] 配置代码检查、格式化、单元测试和浏览器测试。
- [ ] 建立页面路由、布局、加载状态与错误边界。
- [ ] 保留当前静态 Demo 作为迁移对照，不直接覆盖。

完成门槛：正式工程可以独立运行、构建和预览，核心 Schema 与路由稳定。

### 阶段 5：芝加哥完整馆藏

- [ ] 迁移现有馆藏适配层。
- [ ] 实现服务端分页、搜索、筛选和缓存。
- [ ] 实现馆藏浏览与作品详情页面。
- [ ] 实现图片渐进加载、尺寸选择和失败回退。
- [ ] 实现 URL 可分享和浏览器前进、后退状态恢复。
- [ ] 验证大量真实数据下的布局、性能与权利显示。

完成门槛：符合规则的芝加哥馆藏可稳定浏览，作品页面可独立访问和分享。

### 阶段 6：AI 作品内容生成流水线

- [ ] 设计作品内容生成 Schema。
- [ ] 自动生成简介、观察提示、推荐问题、标签、关联、色板和无障碍描述。
- [ ] 将事实、解释和推测分开存储。
- [ ] 建立来源绑定、生成版本和更新时间记录。
- [ ] 建立规则检查与抽样审核机制。
- [ ] 支持失败重试、局部重新生成和人工覆盖。

完成门槛：新作品进入系统后可按统一流程得到可展示、可追溯的增强内容。

### 阶段 7：三个艺术家人格与证据系统

- [ ] 根据馆藏规模、史料质量和人格差异选择约三个艺术家。
- [ ] 建立艺术家人格 Schema。
- [ ] 整理第一手材料、生平时间线和作品资料。
- [ ] 定义语言风格、身份边界、不确定性和拒答规则。
- [ ] 实现作品上下文检索与回答来源绑定。
- [ ] 建立自动评估题库，检查虚构、错引、越界和答非所问。
- [ ] 为 AI 不可用情况准备稳定的本地体验。

完成门槛：三个艺术家人格有明显差异，回答与当前作品相关，并能展示支持回答的依据。

### 阶段 8：真实数据下的最终视觉与动效精修

- [ ] 精修字号、字距、间距、构图和响应式布局。
- [ ] 精修卡片、筛选、切换、加载和页面转场。
- [ ] 精修对话生成节奏、来源展开和观看状态保持。
- [ ] 优化大量图片与复杂动画并存时的性能。
- [ ] 完成鼠标、触控、键盘、全屏和减少动态体验。
- [ ] 完成主流浏览器和常见屏幕尺寸视觉验收。

完成门槛：真实馆藏规模下仍保持一致、流畅、具有辨识度的展示品质。

### 阶段 9：发布与个人作品展示

- [ ] 增加超时、限流、请求体限制、安全响应头和错误回退。
- [ ] 完成域名、HTTPS、生产环境变量和部署。
- [ ] 完成页面标题、描述、图标、站点地图和分享卡片。
- [ ] 编写 About / Case Study，说明产品目标、设计思路、数据来源、AI 边界和个人职责。
- [ ] 制作 30–60 秒演示视频或动图。
- [ ] 完成发布前内容、版权、性能和安全检查。

完成门槛：产品可公开访问，核心体验稳定，并能作为独立个人代表作展示。

## 6. 当前基线与迁移策略

- `experiments/canvas-demo/` 是当前可运行的视觉与交互基线。
- `docs/handoff/2026-07-18-homepage-approved/` 中四张图片是当前批准视觉参考。
- `data/` 是现有馆藏适配与归一化基础。
- `ai/` 是现有提示词和梵高人格实验基础。
- `server.mjs` 是当前静态服务、馆藏 API 和 AI API 原型。
- 正式 Next.js 工程建立后，以上内容按模块逐步迁移；迁移完成前不删除旧 Demo。
