# Canvas MVP 分阶段实施计划

> 文档用途：指导 Canvas MVP 的设计、开发、测试与交付  
> 对应需求文档：Canvas PRD v0.2  
> 当前状态：待评审  
> 更新日期：2026-07-17

## 1. 文档使用方式

本计划只覆盖 PRD 定义的 MVP。项目按阶段顺序推进，每个阶段由若干可检查的小任务组成。阶段内任务可以并行，但进入下一阶段前必须满足本阶段的完成门槛。

任务状态使用以下标记：

- `[ ]` 未开始
- `[-]` 进行中
- `[x]` 已完成

项目推进时，应同时记录每项任务的负责人、计划完成时间、实际完成时间和阻塞问题。

## 2. MVP 目标

MVP 的目标不是验证完整数字博物馆，也不是验证自由 AI 聊天，而是验证用户能否完成以下核心体验：

```text
从地图发现博物馆
  → 进入数字画廊
  → 走近一件作品
  → 观察或选择画面细节
  → 提出或选择一个问题
  → 阅读固定回答并查看依据
  → 回到画面继续观察
  → 选择下一条探索路径
```

## 3. MVP 范围

### 3.1 包含范围

- 桌面端 Web 体验
- 全球地图概念首页
- 芝加哥城市和芝加哥艺术博物馆
- 芝加哥艺术博物馆数字画廊
- 三件梵高作品
- 作品高清查看、缩放、平移、复位和全屏
- 探索细节开关和作品热点
- 推荐问题和固定回答
- 文字输入的交互状态
- 来源展开和推测标记
- 梵高 2.5D 拼贴数字化身
- 语音入口的视觉状态
- 首次使用气泡引导
- 继续逛博物馆和跟随艺术家两条结束路径
- 核心行为埋点和小范围用户测试

### 3.2 不包含范围

- 真实大模型自由对话
- 真实语音识别和语音合成
- 用户账号、收藏和观看历史
- 完整艺术家人生地图
- 自动化每日推荐服务
- 多博物馆和多艺术家
- 移动端专项适配
- 写实 3D 博物馆
- 高拟真人物或视频数字人
- 分享卡片和线下导览

## 4. 总体阶段

| 阶段 | 名称 | 核心产出 |
|---|---|---|
| 阶段一 | 范围、设计与内容准备 | 可直接开发的设计和内容包 |
| 阶段二 | 工程与数据基础 | 正式前端工程和结构化内容 |
| 阶段三 | 地图到画廊的发现路径 | 用户可以从地图走近作品 |
| 阶段四 | 作品深度观看 | 高清查看器、热点和人物 |
| 阶段五 | 固定对话与证据闭环 | 完整有效观看循环 |
| 阶段六 | 测试、优化与发布 | 可用于用户测试的 MVP |

## 11. 并行工作线

以下工作不需要等待工程阶段完成，应从阶段一开始并行推进。

### 11.1 内容工作线

- 图片与资料授权确认
- 馆藏资料和艺术家书信整理
- 热点和观察问题设计
- 固定回答编写
- 来源核验
- 事实、解释和推测分类
- 内容校对和版本维护

### 11.2 视觉工作线

- 拼贴视觉系统
- 地图地标和信息卡
- 数字画廊构图
- 梵高人物分层素材
- 人物动作关键帧
- 作品页和对话区域
- 热点、来源和状态图标
- 图片与动画资源压缩

## 12. 项目推进原则

1. 作品观看和对话闭环优先于地图复杂度。
2. 三件作品全部完成后，再考虑增加第四件作品。
3. 固定回答体验通过用户测试前，不接入真实 AI。
4. 每条回答必须有依据或明确的推测标记。
5. 每条回答都应引导用户重新看向画面。
6. 新增视觉效果不能牺牲交互可读性和性能。
7. 外部图片、地图和字体资源必须准备失败降级方案。
8. 阶段完成以验收结果为准，不以任务代码是否写完为准。

## 13. MVP 后续决策点

MVP 用户测试结束后，根据以下问题决定是否进入真实 AI 阶段：

- 用户是否愿意主动提问？
- 推荐问题是否降低了提问门槛？
- 回答是否促使用户重新观看作品？
- 用户是否理解来源和推测标记？
- 用户是否愿意继续看下一件作品？
- 固定回答的机械感是否是当前体验的主要障碍？
- 内容制作成本是否可以接受？
- 高清图片的授权和交付方式是否可持续？

只有核心观看循环得到验证，才进入真实 AI、语音、账号和内容规模化阶段。
