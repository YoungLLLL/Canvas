复杂搜索已经从会忽略硬过滤的顶层 `q + query` 组合，改为同一 Elasticsearch `bool.must`
中的 `multi_match`。分页使用搜索端点明确支持的 `from/size`，并对最后一个可访问页缩小
`size`，避免请求越过 10,000 条窗口。

高频人工抽查曾触发馆方匿名限流并返回 403。正式浏览器测试已改为单线程，服务端同时提供
短期缓存、一次重试、陈旧回退和明确错误画面，不把上游失败误写成空结果或作品撤下。

## 3. 图片交付路径

当前执行环境访问 ARTIC `www.artic.edu/iiif/2` JPEG 端点会进入 Cloudflare JavaScript
挑战；`info.json`、ARTIC API 和 IIIF Manifest 可访问，但 Manifest 最终仍指向同一受挑战的
JPEG 地址。普通 `<img>` 无法完成顶层网页挑战，因此正式页面不再把 ARTIC IIIF 作为图片
交付路径。

作品与权利状态继续以 ARTIC 为权威来源。图片通过 Wikidata 的 ARTIC artwork ID 属性
`P4610` 精确映射到 Wikimedia Commons，不使用标题模糊匹配；映射后再次读取 Commons
机器可读许可，只接受 Public Domain 或 CC0 图片。ARTIC 与 Wikidata 权利状态冲突时以 ARTIC
为准。没有可信映射的记录降级为仅资料状态，不再请求已知会失败的 ARTIC JPEG。
