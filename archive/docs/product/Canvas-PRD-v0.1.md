# Canvas 产品需求文档（PRD）

> 版本：v0.1  
> 状态：概念验证 / 高保真原型前  
> 更新日期：2026-07-17  
> 首期内容：芝加哥艺术博物馆 × 文森特·梵高

---

## 1. 产品概述

### 1.1 一句话定义

Canvas 是一个可探索、可观看、可与艺术家数字化身对话的数字博物馆。用户从世界地图发现博物馆或艺术家，走进数字画廊，近距离观看高清作品，并通过文字或语音与作品创作者交流。

### 1.2 产品愿景

让不懂艺术史的普通人，也能自然地走近一件艺术品，并通过观察和对话建立自己的理解。

### 1.3 核心价值

1. **发现**：把分散在世界各地博物馆中的艺术品组织成可探索的地图。
2. **观看**：以高清图像、细节缩放和空间化画廊提供沉浸式观展体验。
3. **对话**：用基于可靠史料构建的艺术家数字化身降低理解门槛。
4. **连接**：让用户在博物馆馆藏体系和艺术家人生体系之间自由切换。

---

## 2. 背景与机会

传统数字馆藏通常以搜索、分类和作品资料卡为中心，信息可靠，但普通用户容易面临三个问题：

- 不知道从哪里开始看；
- 看到了作品，却不知道应该观察什么；
- 阅读了介绍，仍然没有形成与作品的个人连接。

Canvas 的机会是把“数据库式浏览”转化为“空间探索 + 深度观看 + 人格化对话”。产品不试图替代实体博物馆，而是成为用户认识作品、理解作品和计划线下参观的入口。

---

## 3. 目标与非目标

### 3.1 第一阶段目标

- 验证世界地图是否能激发无明确目标用户的探索兴趣。
- 验证数字画廊和“走近作品”动画是否能建立观展仪式感。
- 验证艺术家数字化身是否能促进用户主动提问。
- 验证作品热点是否能把观看行为自然转化为对话。
- 建立一套可复用的波普杂志拼贴视觉系统。

### 3.2 第一阶段非目标

- 不建设完整的全球艺术品数据库。
- 不开发用户账号、收藏和观展历史。
- 不开发作品或对话分享功能，仅在架构中预留。
- 不接入真实 AI，自由提问暂不作为原型验收范围。
- 不制作完整移动端原型。
- 不制作写实 3D 博物馆或高拟真人物。

---

## 4. 目标用户

### 4.1 核心用户

对艺术感兴趣，但缺乏艺术史知识的普通用户。

### 4.2 典型特征

- 认识梵高、莫奈等知名艺术家，但不了解具体创作背景；
- 偶尔看展或在社交媒体看到艺术品；
- 愿意探索，但不愿先阅读大量资料；
- 面对艺术品时常有感受，却不知道如何提出问题；
- 更偏好视觉、空间和对话，而不是学术文章式学习。

### 4.3 首次使用动机

用户通常没有明确目标，只是想随便看看、发现有趣的艺术品。

### 4.4 核心用户任务

> “带我发现一件值得看的作品，让我知道该看什么，并帮助我理解自己的感受。”

## 5. 产品设计原则

1. **作品优先**：界面服务于观看，默认不在画面上堆叠说明。
2. **探索先于学习**：先让用户发现，再在需要时提供知识。
3. **用户先开口**：艺术家不主动讲解，不把观展变成强制导览。
4. **沉浸但不冒充**：保持艺术家口吻，同时明确其数字化身身份。
5. **事实与推测分离**：没有史料支持时，必须用小字标注合理推测。
6. **逐层展开**：全球、城市、博物馆、画廊、作品、细节逐步深入。
7. **统一而可扩展**：使用统一拼贴设计系统，不为每位艺术家重新设计产品。

## 6. 信息架构

### 6.1 一级导航

| 一级入口 | 作用 | 第一阶段状态 |
|---|---|---|
| 博物馆 | 从全球地图探索城市、博物馆和馆藏 | 完整主路径 |
| 艺术家 | 从艺术家人生路线探索地点和作品 | 概念入口 |
| 每日艺术 | 根据当天日期推荐相关作品 | 概念入口 |
| 搜索 | 搜索城市、博物馆、艺术家和作品 | 原型可简化 |
| 个人中心 | 收藏、历史、分享记录 | 后续版本 |

### 6.2 两套探索体系

#### 博物馆体系

全球地图 → 城市 → 具体博物馆 → 数字画廊 → 单件作品 → 艺术家对话

#### 艺术家体系

今日艺术家 → 人生世界地图 → 城市与创作阶段 → 当地代表作品 → 艺术家对话

两套体系在单件作品页面汇合，并在观展结束后互相导流。

## 7. 核心用户旅程

### 7.1 第一阶段完整主路径

1. 用户打开 Canvas。
2. 通过轻量气泡了解地图、作品和对话三个核心能力。
3. 首页默认展示全球博物馆地图。
4. 全球视角显示城市；放大地图后显示具体博物馆。
5. 用户点击芝加哥，再点击芝加哥艺术博物馆。
6. 页面通过镜头移动进入数字画廊。
7. 中央展示博物馆代表作，两侧展示其他作品。
8. 用户横向移动画廊，将作品切换到中央。
9. 用户点击中央作品。
10. 镜头执行“走近作品”动画，画框逐步放大为观看主体。
11. 艺术家 2.5D 拼贴人物出现在作品旁边，保持安静并注视用户。
12. 用户通过推荐问题、文字或语音开始交流。
13. 用户可打开“探索细节”，点击热点后自动聚焦细节并获得相关问题。
14. 对话气泡在艺术家旁的固定区域内左右堆叠、内部滚动。
15. 用户结束观看时选择“继续逛博物馆”或“跟随艺术家”。

### 7.2 用户旅程中的情绪目标

| 阶段 | 用户感受目标 |
|---|---|
| 地图 | 世界很大，但我知道可以从哪里开始 |
| 城市与博物馆 | 我正在发现真实存在的艺术目的地 |
| 数字画廊 | 我像进入了一个具有空间感的展览 |
| 走近作品 | 现在只剩下我、作品和艺术家 |
| 对话 | 我的问题不需要专业，也值得被回答 |
| 离开作品 | 我想继续探索，而不是结束任务 |

## 8. 功能需求

### 8.1 首页：全球博物馆地图

#### 功能

- 默认显示世界地图和已开放城市。
- 全球缩放层显示城市聚合地标。
- 放大后显示具体博物馆地标。
- 点击城市或博物馆弹出拼贴信息卡。
- 信息卡展示城市、博物馆、代表作品数量和缩略图。
- 提供每日推荐艺术品入口。
- 提供博物馆 / 艺术家体系切换入口。
- 首次使用显示可跳过的气泡引导。

#### 交互规则

- 地标以颜色和形状区分博物馆、艺术家和每日推荐。
- 地图显示的是馆藏机构，不等于作品当天一定处于公开展出状态。
- 信息卡不能完全遮挡当前地标。
- 用户点击信息卡主按钮后，镜头移动至目标博物馆并进入数字画廊。

### 8.2 地图缩放层级

| 层级 | 展示内容 |
|---|---|
| 全球 | 城市、开放状态、每日推荐 |
| 区域 | 城市名称、博物馆数量、艺术品数量 |
| 城市 | 具体博物馆、代表作品缩略图 |
| 博物馆 | 入口卡片和进入画廊动作 |

### 8.3 每日推荐艺术品

#### 推荐逻辑

优先寻找当天日期与作品之间的可靠关联：

- 创作、展出或收藏事件；
- 艺术家书信或人生事件；
- 作品描绘的节日或历史事件；
- 其他有明确资料依据的日期联系。

如果当天没有足够可靠的关联，则从可用作品中随机推荐，不制造虚假的“历史上的今天”。

#### 展示要求

- 显示作品、艺术家和推荐理由。
- 有日期关联时提供来源标记。
- 没有日期关联时使用“今日随机发现”表述。

### 8.4 博物馆数字画廊

#### 页面布局

- 中央突出一件代表作。
- 左右两侧展示其他重要作品。
- 用户可横向移动或使用方向控制切换作品。
- 当前作品居中、放大、提高对比度；两侧作品降低视觉权重。
- 博物馆介绍和筛选信息退居次要位置。

#### 交互规则

- 点击侧边作品：平滑移动到中央。
- 点击中央作品：执行“走近作品”动画。
- 画廊应具有空间感，但保持拼贴构成，不追求写实 3D。

### 8.5 走近作品动画

#### 动画阶段

1. 环境声音和画廊背景降低。
2. 摄像机沿短路径靠近中央画作。
3. 画框、展墙和其他作品产生不同速度的视差。
4. 中央作品逐渐占据主要画面。
5. 艺术家拼贴人物从侧边图层进入或被镜头揭示。
6. 对话输入和推荐问题在动画结束后出现。

#### 体验约束

- 动画目标是建立“走近”的感受，不应过长。
- 建议时长 1.2～2.0 秒，原型阶段对比测试。
- 支持减少动态效果的系统设置。

### 8.6 作品观看器

#### 默认状态

- 显示高清作品。
- 支持缩放、平移、复位和全屏。
- 不显示热点，保证画面干净。
- 显示作品名称、年份、材料、收藏机构和来源入口。

#### 探索细节模式

- 用户主动打开“探索细节”后显示热点。
- 点击热点后，画面自动缩放并聚焦相应区域。
- 不自动讲解，只展示与该区域相关的推荐问题。
- 用户选择问题或自行输入后，艺术家开始回答。

### 8.7 艺术家数字化身

#### 视觉形态

- 统一品牌体系下的 2.5D 风格化全身拼贴人物。
- 由照片、纸片、印刷网点和手撕边缘构成。
- 不追求真人级拟真，不使用冒充真实人物的视频形象。
- 具备轻微呼吸、转头、注视和看向作品的动作。

#### 初始行为

- 用户进入作品后，艺术家保持安静。
- 通过注视或轻微动作表达“可以交流”。
- 界面提供若干推荐问题，降低首次提问门槛。
- 艺术家只在用户提问或选择推荐问题后回答。

### 8.8 对话系统

#### 输入方式

- 文字输入。
- 语音输入。
- 用户可随时关闭声音并只使用字幕。

#### 输出方式

- 艺术家声音。
- 艺术家旁的对话气泡。
- 用户问题与艺术家回答在同一区域左右区分。
- 气泡连续向上堆叠，区域固定高度并内部滚动。

#### 回答长度

- 根据问题复杂度自动调整。
- 简单事实保持简短。
- 复杂背景可展开，但避免百科全书式长篇独白。

#### 原型实现

- 第一版只使用预设问题和固定回答。
- 需要覆盖正常提问、细节提问、史料不足和查看依据等关键状态。
- 真实 AI 和自由提问进入后续版本。

### 8.9 事实、推测与来源

- 回答旁显示轻量“依据”标记。
- 点击后展开馆藏页面、艺术家书信或研究资料。
- 史料没有明确答案时，数字化身可以保持艺术家口吻提供合理解释。
- 此类内容必须显示小字：**“基于现有史料的合理推测，并非艺术家的明确记录。”**
- 页面持续显示数字化身身份说明，但不反复打断对话。

### 8.10 观展结束分流

作品页同时提供两条下一步路径：

1. **继续逛博物馆**：返回当前数字画廊，观看相邻馆藏。
2. **跟随艺术家**：进入艺术家人生地图，沿城市和创作阶段探索作品。

## 9. 艺术家体系

### 9.1 默认状态

- 默认展示“今日艺术家”的人生路线。
- 用户可搜索或切换其他艺术家。
- 第一阶段只制作概念入口，不实现完整路径。

### 9.2 路线内容

- 出生地点；
- 生活和迁徙城市；
- 重要创作阶段；
- 当地代表作品；
- 重要人生事件；
- 去世地点及后续馆藏流向。

### 9.3 梵高示例路线

荷兰 → 巴黎 → 阿尔勒 → 圣雷米 → 奥维尔

路线以拼贴地标、虚线轨迹、时间标签和作品卡片构成。

## 10. 视觉与品牌系统

### 10.1 核心风格

> 波普艺术 × 现代杂志 × 手撕拼贴 × 2.5D 空间。

### 10.2 视觉关键词

- 手撕纸边；
- 纸张叠层和真实投影；
- 印刷网点与颗粒；
- 错位套色；
- 杂志式大字号排版；
- 明亮波普色块；
- 立体地形和视差；
- 票据、标签、档案卡和便签式组件。

### 10.3 建议基础色

- 暖白纸张；
- 天空浅蓝；
- 酸性黄绿色；
- 珊瑚红；
- 薰衣草紫；
- 炭黑；
- 苔藓绿。

最终颜色比例由静态高保真原型确认。

### 10.4 统一性原则

- 所有艺术家使用同一套 Canvas 视觉组件。
- 不为不同艺术家重做完整主题。
- 艺术家差异通过肖像、作品、内容和少量局部素材表现。
- 地图、画廊、人物、气泡和来源卡全部使用同一拼贴语言。

## 11. 高保真原型计划

### 11.1 制作方式

先使用图像生成确定静态高保真页面，再基于选定画面制作真实交互网页。不先投入复杂前端动效。

### 11.2 必须生成的关键画面

| 编号 | 原型画面 | 需要验证的问题 |
|---|---|---|
| P01 | 全球博物馆地图首页 | 拼贴地图是否清晰、是否有探索欲 |
| P02 | 芝加哥城市 / 博物馆放大状态 | 缩放层级和信息卡是否自然 |
| P03 | 芝加哥艺术博物馆数字画廊 | 中央代表作与两侧作品的空间关系 |
| P04 | 走近作品动画结束帧 | 作品、艺术家和对话入口如何共存 |
| P05 | 艺术家对话状态 | 气泡堆叠、人物动作和作品观看是否冲突 |
| P06 | 探索细节状态 | 热点、自动聚焦和推荐问题的层级 |
| P07 | 观展结束分流 | 两条后续路径是否容易理解 |

### 11.3 原型评审顺序

1. 先确定 P01 的视觉语言。
2. 将同一系统延伸到 P03 和 P04。
3. 确定艺术家人物样式与对话区域。
4. 补齐细节模式和结束分流。
5. 完成整条可点击主路径。
6. 再进入真实网页开发。

## 13. 内容与数据要求

每件作品至少需要：

- 中英文名称；
- 艺术家；
- 年份、材料、尺寸；
- 收藏机构和馆藏页面；
- 高清图像及使用许可；
- 基础作品说明；
- 3～6 个可探索热点；
- 热点坐标和推荐问题；
- 预设对话及证据类型；
- 艺术家相关书信或一手资料；
- 学术争议和推测边界；
- 推荐下一件作品。

## 14. 成功指标

### 14.1 原型测试指标

- 用户是否能在不被说明的情况下点击城市和博物馆；
- 是否能理解中央作品可以被点击并走近；
- 是否注意到艺术家可以交流；
- 是否会选择一个推荐问题；
- 是否能找到“探索细节”模式；
- 是否理解来源标记和推测说明；
- 是否愿意继续逛博物馆或跟随艺术家。

### 14.2 MVP 行为指标

- 地图到博物馆的进入率；
- 博物馆画廊到作品页的进入率；
- 每件作品的平均观看时长；
- 开启探索细节的用户比例；
- 发起至少一次对话的用户比例；
- 单次体验中的平均有效对话轮数；
- 点击下一件作品或艺术家路线的比例。

### 14.3 初步成功标准

一次核心体验中，用户至少：

- 进入一个博物馆；
- 走近一件作品；
- 探索一个细节或提出一个问题；
- 完成至少两轮对话；
- 主动选择一个后续探索方向。

## 15. 验收标准

### 地图

- 用户能区分城市和博物馆层级。
- 用户能从地图进入芝加哥艺术博物馆。
- 页面明确区分馆藏地和实时展出状态。

### 画廊

- 中央作品始终是最明显的交互目标。
- 用户能将两侧作品切换到中央。
- 走近动画完成后，作品成为视觉主体。

### 对话

- 艺术家在用户提问前不主动讲话。
- 推荐问题始终可见但不遮挡作品。
- 用户与艺术家气泡左右区分并可滚动。
- 每条回答可以查看依据。
- 推测回答必须显示明确标记。

### 视觉

- 所有核心页面使用统一波普杂志拼贴系统。
- 拼贴装饰不能影响文字和交互控件的可读性。
- 地图、画廊和对话空间在视觉上属于同一产品。

## 16. 风险与应对

| 风险 | 应对 |
|---|---|
| 拼贴元素过多导致操作不清楚 | 保持固定组件层级，装饰不承担关键交互 |
| 艺术家人物抢夺作品注意力 | 人物位于作品侧边，动作克制，用户提问前保持安静 |
| 地图让用户误以为作品正在展出 | 明确标注“馆藏机构”与展出状态差异 |
| 固定回答使对话显得机械 | 原型只验证交互；正式版本接入知识检索与 AI |
| 推测内容被误认为史实 | 强制推测标记，所有回答提供依据入口 |
| 不同艺术家增加视觉制作成本 | 统一拼贴组件，仅替换内容和人物素材 |
| 高清图像授权不明确 | 只使用明确开放许可或获得授权的图像 |

## 17. 待高保真原型确认项

- 走近作品动画时长和镜头曲线；
- 语音开启、关闭和播放状态；
- 每日推荐卡在地图中的具体位置；
- 首次气泡引导的文案与出现顺序。
