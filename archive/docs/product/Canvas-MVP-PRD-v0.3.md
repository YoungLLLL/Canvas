# Canvas 最小可行产品需求文档（MVP PRD）

> 版本：v0.3  
> 状态：执行基准 / 可进入前端实现  
> 更新日期：2026-07-18  
> 首期内容：芝加哥艺术博物馆 × 文森特·梵高  
> 适用范围：桌面端最小闭环  
> 替代关系：本文件取代 `Canvas-PRD-v0.2.md`，作为当前 MVP 的产品、设计与开发依据。

## 0. 本版关键决策

- 产品核心收敛为：**观看艺术品，并围绕当前作品与艺术家进行可信对话**。
- 地图首页负责发现与进入，不承担复杂地理探索。
- 数字画廊采用虚拟作品卡轮播，不模拟写实 3D 或实体展厅。
- 作品详情页只保留高清观看与单侧对话两个核心能力。
- 作品支持放大、缩小、拖动、复位和全屏。
- 对话始终与作品并列，不能覆盖作品；用户对话时仍可操作画面。
- 回答提供依据入口，并明确数字化身与史料边界。
- 作品热点、细节探索、自动聚焦和艺术家生涯路线全部延期。
- 首期不接入真实 AI；使用预设问题、固定回答和边界回复验证交互。
- 4 张已确认原型图是视觉基准；网页必须重建真实结构，不能把 PNG 直接作为页面背景。

## 1. 执行摘要

Canvas 是一个面向普通艺术爱好者的数字艺术观看与对话体验。用户从全球博物馆入口发现芝加哥艺术博物馆，进入由三件梵高作品组成的虚拟数字画廊，选择作品后进行高清观看，并在作品始终可见的前提下与梵高数字化身对话。MVP 不追求馆藏规模、复杂地图或完整艺术史课程，而是验证一个最小闭环：**用户是否会因为可信、与画面相关的艺术家回答而继续观看作品。**

### 1.1 一句话定义

> 从博物馆进入一件作品，边看边问，和艺术家一起重新观看。

### 1.2 产品主张

> **走近作品，问出你的问题。**

### 1.3 MVP 核心假设

我们相信：如果不具备艺术史背景的用户可以在高清作品旁直接提出自然问题，并获得有史料边界、能够重新指向画面的艺术家回答，他们会更愿意停留、继续观察并形成对作品的个人理解。

---

## 2. 问题陈述

### 2.1 谁遇到这个问题

对艺术感兴趣、认识梵高等知名艺术家，但缺乏系统艺术史知识的普通用户。

### 2.2 用户问题

- 用户面对数字馆藏时不知道从哪里开始。
- 用户看到作品后，常常只停留几秒，不知道还能观察什么。
- 传统作品介绍可靠但偏单向阅读，难以回应用户当下的真实疑问。
- 通用聊天界面脱离作品，容易把注意力从观看变成长篇阅读。
- “模拟艺术家本人”的体验如果没有来源边界，容易让用户把推测误认为史实。

### 2.3 用户影响

- 用户很难进入一件作品，也很难建立个人感受。
- 作品被当成缩略图或知识条目，而不是可持续观看的对象。
- 用户不会继续提问，也没有动力返回画面。

### 2.4 产品机会

Canvas 不建设另一个大型数字馆藏，而是把真实博物馆、作品选择、高清观看和可信对话组织成一条连续路径。地图降低开始门槛，画廊建立选择感，作品页承载最终价值。

### 2.5 当前证据状态

本阶段主要证据来自产品假设、现有静态 Demo 和连续原型评审，尚无正式用户测试数据。MVP 的首要任务是获取真实行为数据，而不是证明预设结论。

## 3. 目标用户与核心任务

### 3.1 主要用户

**好奇但非专业的艺术观看者**

- 偶尔参观博物馆或在社交媒体接触艺术品。
- 愿意探索，但不愿先阅读长篇资料。
- 对作品有直觉感受，却不知道如何组织问题。
- 更偏好视觉、空间与对话，而不是课程式学习。
- 使用桌面或较大屏幕完成沉浸观看。

### 3.2 次要用户

- 希望以更轻方式了解馆藏的博物馆访客。
- 教师、学生或内容创作者，可将 Canvas 作为作品讨论入口。

### 3.3 Jobs to Be Done

> 当我想随便看看艺术但不知道从哪里开始时，带我进入一件值得看的作品；当我产生疑问时，让我能直接询问，并通过回答发现画面中之前没有注意到的东西。

## 4. 目标、成功定义与非目标

### 4.1 MVP 目标

1. 验证用户能否从博物馆入口顺利进入数字画廊。
2. 验证专辑封面式作品轮播是否能让用户理解作品可切换、可点击。
3. 验证作品卡翻转是否能建立从画廊进入观看状态的连续感。
4. 验证用户能否在详情页自然使用缩放、拖动、复位和全屏。
5. 验证艺术家单侧对话是否会促进用户提问、追问或查看依据。
6. 验证回答之后，用户是否会再次操作或观察作品。

### 4.2 北极星行为

一次“有效观看与对话循环”定义为：

```text
进入作品
  → 操作或观看作品
  → 提出或选择一个问题
  → 阅读艺术家回答
  → 再次操作作品、继续追问或查看依据
```

### 4.3 明确非目标

- 不建设完整全球馆藏数据库。
- 不制作写实 3D 博物馆或自由行走空间。
- 不制作作品热点、细节探索或自动聚焦。
- 不制作梵高生涯地图或“跟着梵高”路线。
- 不制作语音输入、语音输出或自动播放。
- 不接入真实大模型、知识检索或自由生成回答。
- 不建设账号、收藏、历史、分享和个人中心。
- 不制作完整搜索结果页。
- 不制作移动端专项体验。
- 不提供票务、开放时间、实时展出状态或行程规划。

## 5. 解决方案概述

### 5.1 产品结构

MVP 包含 3 个路由页面：

| 页面代码 | 页面 | 建议路由 | 作用 |
|---|---|---|---|
| `MAP` | 全球博物馆入口 | `/` | 发现今日作品与芝加哥艺术博物馆 |
| `GAL` | 芝加哥艺术博物馆数字画廊 | `/museum/chicago-art-institute` | 在三件梵高作品之间切换 |
| `ART` | 单件作品观看与对话 | `/artwork/[artworkId]` | 放大观看、与艺术家对话、查看依据 |

艺术家生涯路线 `ARI` 不进入本次 MVP。

### 5.2 最小用户流程

```text
MAP 首页首屏
  → 下滑至博物馆信息
  → 点击“进入数字画廊”
  → GAL 浏览三件作品卡
  → 点击中央作品卡或作品下方对话入口
  → 卡片翻转并进入 ART
  → 放大、拖动或全屏观看
  → 与梵高对话
  → 查看回答依据或继续追问
  → 返回数字画廊，恢复当前作品位置
```

### 5.3 两种进入作品页的方式

| 入口 | 作品页初始状态 |
|---|---|
| 点击中央作品卡 | 作品可观看；右侧显示梵高身份与紧凑聊天入口 |
| 点击“想和梵高聊聊这幅画？” | 进入同一路由；右侧直接显示对话状态并聚焦输入框 |

两种入口不得产生两个不同的作品路由。

### 5.4 核心能力

- 从博物馆进入三件作品组成的数字画廊。
- 横向切换作品，当前作品成为视觉中心。
- 当前作品生成全屏模糊色彩背景。
- 作品卡翻转进入详情页。
- 高清作品缩放、拖动、复位和全屏。
- 单侧艺术家对话、推荐问题、继续追问。
- 回答依据与推测边界。
- 返回数字画廊并恢复之前的作品位置。

### 5.5 已确认视觉基准

以下 4 张原型图是当前实现的视觉基准。

#### 01 — 首页首屏

![Canvas 首页首屏](../handoff/2026-07-18-homepage-approved/01-home-hero-approved.png)

关键要求：

- 今日作品是第一视觉中心。
- 右侧使用暖灰透明玻璃对话入口。
- 艺术家身份使用画作中的眼睛，不使用完整头像或机器人图标。
- 下方深石墨地球被视口裁切，并保留大型 `CANVAS Library`。

#### 02 — 博物馆信息状态

![芝加哥艺术博物馆信息](../handoff/2026-07-18-homepage-approved/02-museum-info-approved.png)

关键要求：

- 页面下滑后地球移动到右侧，左侧展示当日作品所属博物馆。
- 主动作只有“进入数字画廊”。
- 不堆叠票务、开放时间等非必要信息。

#### 03 — 数字画廊默认状态

![数字画廊默认状态](../handoff/2026-07-18-homepage-approved/03-gallery-default-approved.png)

关键要求：

- 使用虚拟作品卡轮播，不模拟实体展厅。
- 每件作品由画作与底部窄资料栏组成完整圆角卡。
- 当前作品最大，两侧作品降低权重并保持可识别。
- 背景使用当前作品放大、模糊后的色彩场。
- 对话入口位于当前作品卡下方。

#### 04 — 作品观看与艺术家对话

![作品观看与艺术家对话](../handoff/2026-07-18-homepage-approved/04-artwork-dialogue-approved.png)

关键要求：

- 左侧作品始终可见、可操作，是页面第一主体。
- 右侧只承担艺术家身份、对话、推荐问题和依据。
- 对话使用编辑式文本排版，不使用彩色聊天气泡。
- 输入框固定在右侧底部。
- 不显示热点、细节模式或艺术家路线入口。

### 5.6 视觉方向

- 严肃、严谨、人文、安静，接近国际博物馆档案和艺术出版物。
- 页面以暖石色、墨黑和深石墨为基础。
- 艺术品是主要高饱和色彩来源。
- 大标题使用人文衬线字体；导航、按钮和元数据使用克制无衬线字体。
- 透明玻璃只用于关键对话入口和必要浮层，不扩散到所有组件。
- 避免卡通、贴纸、波普拼贴、霓虹玻璃、普通聊天软件和过度圆角卡片。

## 6. 功能需求

### 6.1 `MAP` — 首页首屏

#### 内容

- CANVAS 品牌与一级导航。
- 之前推荐作品、今日作品和艺术家对话入口。
- 当前博物馆定位与深石墨地球。
- 大型 `CANVAS Library` 标题。

#### 行为

- 页面支持向下滚动进入博物馆信息状态。
- 今日作品可直接进入对应作品页；该快捷路径不是首轮验收阻塞项。
- 首页对话入口只展示一句说明、一个问题提示和一个主要动作，不展示对话历史。

### 6.2 `MAP` — 博物馆信息状态

#### 内容

- 芝加哥艺术博物馆中英文名称。
- 所在城市和国家。
- 一句馆藏说明。
- 今日推荐作品缩略图与基础资料。
- Canvas 当前开放作品数量。
- “进入数字画廊”主按钮。

#### 行为

- 点击“进入数字画廊”进入 `GAL`。
- 地球可保持视觉拖动或轻量旋转，但复杂地图索引不阻塞 MVP。

### 6.3 `GAL` — 数字画廊

#### 内容

- 《卧室》《自画像》《诗人的花园》三张统一圆角作品卡。
- 当前作品的大尺寸卡片。
- 两侧上一件与下一件作品。
- 当前作品底部窄资料栏：名称、艺术家、年份、序号。
- 当前作品下方艺术家眼睛头像与聊天入口。
- 当前作品生成的全屏模糊背景。
- 拖动/切换提示、左右控制和作品序号。

#### 行为

- 点击侧边作品：该作品平滑移动到中央。
- 拖动或横向滚动：切换当前作品。
- 当前作品、资料、序号和背景色场同步更新。
- 点击中央作品卡：整张卡沿 Y 轴翻转并进入 `ART`。
- 点击聊天入口：进入 `ART` 并直接打开右侧对话状态。
- 返回画廊时恢复离开前的当前作品。

#### 动画约束

- 作品切换建议 400～650 ms。
- 进入作品页的翻转与位移建议总时长 700～1100 ms。
- 动画不能阻止用户快速导航。
- `prefers-reduced-motion` 下使用淡入、淡出和位置切换替代 3D 翻转。

### 6.4 `ART` — 作品观看器

#### 必须能力

- 放大。
- 缩小。
- 拖动画面。
- 复位。
- 全屏。

#### 观看规则

- 作品保持原始比例，不拉伸、不裁掉关键内容。
- 初始状态完整显示作品。
- 缩放围绕指针位置或画面中心进行。
- 拖动范围应防止作品完全离开视口。
- 复位恢复初始比例和位置。
- 控件位于作品下方或作品区底部，不遮挡关键区域。
- 控件闲置时可以降低透明度，但必须可发现、可聚焦。

#### 明确不包含

- 热点。
- 自动聚焦。
- 细节讲解模式。
- 画面内浮动说明。

### 6.5 `ART` — 艺术家对话

#### 初始状态

- 显示 `Van Gogh`、眼睛头像和当前作品资料。
- 显示紧凑聊天入口或 2～3 个推荐问题。
- 艺术家在用户提问前不主动播放长篇回答。

#### 对话状态

- 对话在右侧固定单栏中展开，不覆盖左侧作品。
- 首屏显示一轮用户问题与一轮梵高回答。
- 新消息在右侧栏内部滚动。
- 输入框固定在右侧栏底部。
- 用户可关闭对话，返回紧凑入口状态；不离开作品页。
- 回答使用编辑式文本，不使用彩色气泡。
- 推荐追问使用文字链接或低强调控件。

#### MVP 输入与回复

- 支持文字输入。
- 提供预设推荐问题。
- 已知问题匹配固定回答。
- 未知问题返回边界回复，例如：“这个问题暂时没有足够资料支持。我们可以先看看画面中的颜色、家具或空间。”
- 真实 AI、流式生成和自由知识检索不属于本次 MVP。

#### 回答原则

- 回答应尽可能指向当前画面中的颜色、线条、家具、空间或构图。
- 回答简洁，避免百科全书式长篇独白。
- 艺术家口吻服务于亲近感，史料边界优先于角色沉浸。
- 不把推测写成艺术家真实说过的话。
- 每条主要回答提供依据入口。

### 6.6 来源与边界

- 回答旁显示“查看依据”及来源数量。
- 点击后在右侧栏内或轻量抽屉中展示来源。
- 来源至少区分：馆藏事实、艺术家书信、研究解释、合理推测。
- 合理推测必须明确标注：

> 基于现有史料的合理推测，并非艺术家的明确记录。

- 关闭来源后恢复之前的对话位置与作品缩放状态。

### 6.7 返回与状态恢复

- 作品页提供“返回芝加哥艺术博物馆”入口。
- 返回后恢复当前作品在画廊中央的位置。
- 作品缩放状态不要求跨路由保存。
- 对话状态不要求跨作品保存；切换作品后加载该作品自己的初始问题。

## 7. 首期内容与数据

### 7.1 博物馆

- 芝加哥艺术博物馆（Art Institute of Chicago）。

### 7.2 艺术家

- 文森特·梵高（Vincent van Gogh）。

### 7.3 作品

| 作品 | 年份 | 首期用途 |
|---|---:|---|
| 《卧室》 | 1889 | 默认画廊作品、作品页与对话主样本 |
| 《自画像》 | 1887 | 画廊作品、艺术家眼睛识别素材 |
| 《诗人的花园》 | 1888 | 画廊作品 |

### 7.4 每件作品最低数据要求

- 中英文名称。
- 艺术家、年份、材料、尺寸。
- 收藏机构与馆藏页面。
- 高清图像与许可信息。
- 一段不超过 80 个汉字的基础介绍。
- 2～4 个推荐问题。
- 每个推荐问题对应的固定回答。
- 回答关联的来源与证据类型。
- 史料不足时的边界回复。
- 当前作品对应的背景主色或自动取色策略。

## 8. 用户故事与验收标准

### 8.1 Epic 假设

如果用户能从真实博物馆入口进入少量精选作品，并在高清作品旁与具有史料边界的艺术家数字化身对话，那么用户会提出问题，并在回答后继续观看作品。

### Story 1 — 从博物馆进入数字画廊

作为一个不知道从哪里开始的用户，我希望从首页看到今天的博物馆并进入画廊，从而快速开始观看。

**验收标准：**

- [ ] 用户下滑后能看到芝加哥艺术博物馆信息。
- [ ] “进入数字画廊”是该区域唯一高强调主动作。
- [ ] 点击后进入 `GAL`，不经过额外详情页。

### Story 2 — 在画廊中切换作品

作为一个浏览者，我希望看到当前作品及相邻作品，从而理解还有其他作品可以选择。

**验收标准：**

- [ ] 当前作品卡明显大于两侧作品卡。
- [ ] 侧边作品仍可识别、可点击。
- [ ] 点击或拖动后，作品、资料、序号和背景同步更新。
- [ ] 键盘用户可通过可聚焦控制切换作品。

### Story 3 — 从作品卡进入详情页

作为一个对当前作品感兴趣的用户，我希望点击作品后连续进入观看状态，而不是感到突然跳页。

**验收标准：**

- [ ] 点击中央卡触发翻转与位移动画。
- [ ] 动画结束后作品成为左侧主要观看区域。
- [ ] 减少动态模式不执行 3D 翻转。
- [ ] 动画过程中重复点击不会产生多次导航。

### Story 4 — 放大观看作品

作为一个观看者，我希望放大并拖动画面，从而观察作品而不被界面打断。

**验收标准：**

- [ ] 支持放大、缩小、拖动、复位和全屏。
- [ ] 作品不被拉伸。
- [ ] 达到缩放边界后不会继续无限放大或缩小。
- [ ] 复位可恢复初始位置与比例。
- [ ] 聊天过程中仍可操作作品。

### Story 5 — 与梵高开始对话

作为一个不懂艺术史的用户，我希望能选择推荐问题或输入自己的问题，从而表达对作品的疑惑。

**验收标准：**

- [ ] 用户可从画廊聊天入口或作品页聊天入口开始对话。
- [ ] 对话始终位于右侧栏，不覆盖作品。
- [ ] 至少提供 2 个推荐问题。
- [ ] 已知问题显示对应固定回答。
- [ ] 未知问题显示边界回复，不虚构事实。
- [ ] 输入框在对话滚动时保持可用。

### Story 6 — 查看回答依据

作为一个希望判断回答可信度的用户，我希望查看回答来自哪里，从而区分事实、解释和推测。

**验收标准：**

- [ ] 每条主要回答旁有“查看依据”。
- [ ] 来源展示对应标题、类型和外部链接或引用信息。
- [ ] 推测内容有明确标记。
- [ ] 关闭来源后恢复原对话位置。

### Story 7 — 返回数字画廊

作为一个完成当前观看的用户，我希望回到博物馆继续浏览其他作品。

**验收标准：**

- [ ] 作品页存在清晰但低强调的返回入口。
- [ ] 返回后当前作品仍位于画廊中央。
- [ ] 用户可以立即选择相邻作品。

## 9. 成功指标

本阶段没有历史基线，以下为首轮可用性测试与 MVP 验证目标，测试后更新。

### 9.1 主要指标

**有效观看与对话循环完成率**

定义：进入作品页的用户中，完成“提问或选择问题 → 阅读回答 → 再次操作作品、继续追问或查看依据”的比例。

- 首轮目标：≥ 40%。

### 9.2 次要指标

| 指标 | 首轮目标 |
|---|---:|
| 无帮助完成核心流程的测试用户比例 | ≥ 80% |
| 博物馆信息到数字画廊进入率 | ≥ 70% |
| 数字画廊到作品页进入率 | ≥ 70% |
| 作品页发起至少一次对话的比例 | ≥ 60% |
| 发起第二轮追问或点击推荐追问的比例 | ≥ 35% |
| 点击“查看依据”的比例 | 记录基线，不设硬目标 |
| 作品页平均停留时长 | 记录基线，不设硬目标 |

### 9.3 质量与护栏指标

- 测试用户能够明确说出艺术家回答并非真实艺术家的实时发言。
- 用户不会把推测内容误认为确定史实。
- 对话区域不能显著降低作品操作成功率。
- 页面关键文字和控件满足 WCAG AA 对比度。
- 桌面核心交互无阻塞性错误。

## 10. 非功能需求

### 10.1 设备与浏览器

- 桌面优先，设计基准为约 `1440 × 960` 或更大视口。
- 支持当前主流桌面 Chrome、Safari、Edge 和 Firefox。
- 较窄桌面可调整比例，但不能把对话覆盖到作品上。

### 10.2 性能

- 首屏布局应先于高清作品完整加载出现。
- 使用响应式图片、预加载当前作品、延迟加载侧边作品。
- 模糊背景优先使用低分辨率衍生图，避免直接模糊超大原图。
- 动画尽量使用 `transform` 和 `opacity`。

### 10.3 可访问性

- 所有按钮、轮播控制和聊天输入可通过键盘操作。
- 图片提供作品名称与艺术家替代文本。
- 焦点状态清晰可见。
- 尊重 `prefers-reduced-motion`。
- 全屏退出、来源关闭和对话关闭均支持 `Esc`。

### 10.4 内容与授权

- 只使用许可明确的高清图像。
- 页面保留作品来源与收藏机构链接。
- 不暗示作品当前正在实体展厅公开展出。

## 11. 边界情况与错误状态

| 场景 | MVP 行为 |
|---|---|
| 高清图加载失败 | 显示低清占位、作品资料和重试动作 |
| 模糊背景加载失败 | 使用作品预设主色渐变或暖灰背景 |
| 用户输入未知问题 | 显示边界回复和推荐问题 |
| 固定回答数据缺失 | 不生成内容；提示当前问题暂无可靠资料 |
| 来源链接不可用 | 保留来源标题并显示暂时无法打开 |
| 对话内容超过一屏 | 右侧栏内部滚动，输入框固定 |
| 用户快速重复切换作品 | 取消前一动画并以最后一次选择为准 |
| 用户在高缩放状态返回画廊 | 正常返回；缩放状态无需保留 |
| 浏览器进入减少动态模式 | 轮播和路由使用淡入淡出，不使用翻转 |

## 12. 依赖、风险与应对

### 12.1 依赖

- 芝加哥艺术博物馆三件作品的许可明确高清素材。
- 每件作品的馆藏资料、书信或研究来源。
- 中英文显示字体与授权。
- 作品查看器的缩放、拖动和全屏实现。
- 预设问题、固定回答和来源数据结构。
- 已确认的 4 张视觉基准图。

### 12.2 风险与应对

| 风险 | 应对 |
|---|---|
| 生图中的文字和比例不可直接复用 | 以生图作视觉基准，使用真实文字和网格重建 |
| 模糊作品背景影响性能或可读性 | 使用低清衍生图、遮罩和对比度检测 |
| 轮播像娱乐播放器而削弱博物馆感 | 保持克制排版、真实资料和艺术品主导色彩 |
| 翻转动画成为噱头或引起不适 | 控制时长，并提供减少动态替代 |
| 固定回答显得机械 | 聚焦少量高质量问题，提供自然追问和边界回复 |
| 用户误认数字化身为真实艺术家 | 持续显示数字化身身份和回答依据 |
| 对话把注意力从作品带走 | 作品始终可见，回答必须包含重新观看落点 |
| 高清素材加载慢 | 响应式图片、预加载、占位和缓存 |
| 旧设计系统与新原型冲突 | 在开发前更新 `Design.md`，以本 PRD 和批准原型为准 |

## 13. 实施原则与阶段

### 13.1 原型到网页

- 原型图用于确定构图、层级、色彩和情绪。
- 网页必须使用真实 DOM、CSS、文本、数据和可访问控件重建。
- 不允许将完整 PNG 作为页面背景来伪造实现。
- 作品图像、背景衍生图和眼睛头像应作为独立素材管理。

### 13.2 推荐实施顺序

1. 更新 `Design.md`：颜色、字体、圆角、玻璃、间距和动效。
2. 整理三件作品的高清素材、缩略图、背景衍生图和眼睛头像。
3. 重建全局 Header、按钮、作品卡、聊天输入和来源面板。
4. 实现 `MAP` 首屏与博物馆信息状态。
5. 实现 `GAL` 作品轮播、背景切换和卡片翻转。
6. 实现 `ART` 作品查看器。
7. 实现固定回答对话、推荐追问和来源。
8. 串联返回状态与路由。
9. 完成响应式、键盘和减少动态模式。
10. 进行首轮可用性测试并更新指标与范围。

### 13.3 现有工程基础

`experiments/canvas-demo/` 是当前无构建依赖的静态 Demo，已有缩放、拖动、全屏和本地规则式对话能力。下一阶段可在评估后选择：

- 直接重构现有 HTML/CSS/JavaScript Demo；或
- 将验证通过的交互迁移到正式前端工程。

首轮实现优先验证体验，不因框架迁移阻塞核心流程。

## 14. 开放问题

以下问题不阻塞首轮页面搭建，但必须在上线或正式用户测试前确认：

1. 首轮是否保留首页“今日作品”直接进入作品页的快捷路径。
2. 作品页点击作品卡进入时，右侧默认显示推荐问题还是仅显示聊天入口。
3. 来源在右侧栏内切换，还是使用覆盖式轻量抽屉。
4. 聊天固定回答覆盖哪些问题，未知问题如何归类。
5. 三件作品的背景取色使用手工配置还是自动算法。
6. 卡片翻转的最终时长、缓动曲线与减少动态替代方案。
7. 首轮测试使用本地静态 Demo，还是先迁移到正式工程。
